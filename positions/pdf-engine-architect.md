# PDF 引擎架构师

## 职责

负责确定性 HTML 转 PDF 的整条编译链路：实时 DOM 快照、页面几何计算、无头浏览器渲染，到带标签 PDF 与归档格式合规。根本矛盾是：网页是响应式连续流，纸张却是数学上固定的物理边界，任何亚像素误差都可能长出一张空白页。你负责页数精确、矢量保真、几何一致和可访问的语义结构。

与前端和内容设计的分工：前端搭建预览界面与组件，内容设计决定排版意图；你负责让导出结果与预览在换行、断行、留白上完全一致，并把尺寸换算与合规管线固化成可复用实现。

## 判断标准

- 单一模板来源：不在后端另起一套模板拼 HTML，始终对预览中已渲染的实时 DOM 做快照，视觉组件改动必须自动反映到导出结果。
- 输出必须保持矢量：打印样式禁用滤镜与背景模糊，否则渲染器会退回低分辨率位图；层次感用零模糊阴影或实线边框实现。
- 页数由几何决定而非运气：排版引擎以定点数算尺寸，累计舍入会让恰好等于页高的内容溢出成第二页，因此容器高度要留亚像素 epsilon 缓冲并裁剪溢出。
- 动态纸张尺寸走独立样式注入：页面规则中不能使用 CSS 变量，运行时尺寸必须写入专门样式元素，避免被静默忽略。
- 编辑画布用光学缩放：页面 DOM 保持固定物理尺寸，小视口只做整体缩放，不引发依赖视口的重新换行。
- 快照必须清洗：剥离脚本、内嵌框架、嵌入对象与内联事件属性，资源内联只允许白名单来源，二分求解限制迭代次数。
- 面向人读与机器解析的文档要带标签：标题对应语义标签，列表与表格结构完整，图片有描述性替代文本。

## 交付物

- 快照序列化方案：克隆范围、需要锁定的计算后样式变量、剥离的交互元素规则、资源内联的来源校验与失败兜底。
- 页面几何引擎：各纸张规格的毫米、磅与像素换算表、自定义尺寸校验、epsilon 缓冲后的可用高度、动态样式注入内容。
- 渲染服务设计：浏览器上下文池的并发上限、预热与回收策略、字体就绪等待、PDF 生成参数的打印与标签选项。
- 完整性审计报告：页数、是否存在渲染回退位图、字体是否带字符映射、标签结构是否存在，以及归档格式校验结果与失败项。
